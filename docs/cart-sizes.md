# Корзина и выбор размера

Плюс в каталоге, избранном и подборках сразу добавляет товар. Если у товара ровно один настоящий вариант, выбирается он. Иначе строка сохраняет `variantId: null` и количество, а размер покупатель выбирает в корзине. Единственный доступный вариант среди нескольких не выбирается автоматически.

`cart_pending_sizes` хранит невыбранные строки отдельно от существующих `carts` с вариантами. Аддитивная миграция 6 сохраняет прежние корзины. Все изменения и оформление используют одну блокировку посетителя. Невыбранные строки не создают фиктивных вариантов или резервов; сервер проверяет опубликованность, цену и доступное количество. Перед созданием заказа с невыбранным размером возвращается `SIZE_REQUIRED`.

## HTTP

- `POST /api/cart { productId, quantity }` добавляет товар, откладывая размер при нескольких вариантах.
- Прежний `POST /api/cart { variantId, quantity }` добавляет выбранный вариант.
- `PATCH /api/cart { productId, quantity }` меняет количество невыбранной строки; `variantId` адресует выбранную строку. Ноль удаляет её.
- `PATCH /api/cart { productId, selectVariantId, quantity }` выбирает размер; вместо `productId` можно передать исходный `variantId` для смены размера. Переносится всё актуальное количество исходной строки, а не устаревшее количество клиента. Совпадающий целевой вариант объединяется, его наличие проверяется до изменения.

Клиентская очередь в `cart-store.ts` показывает изменения сразу и записывает их последовательно. Проекция и отправка выбора размера заново учитывают актуальное количество после начального GET и предыдущих операций. Неоднозначный сбой сверяется с сервером; неудавшееся добавление не удаляет существующую целевую строку. Локально не сохраняются копии приватной корзины или платёжных данных.

Нативные элементы корзины включаются после подключения обработчиков, без ожидания начального GET. Серверный HTML показывает состав корзины и при выключенном JavaScript. Перед оформлением очередь завершается и сервер проверяет актуальные цены, размеры и остатки.

## Проверки

`packages/core/test/deferred-cart.test.ts` проверяет сохранение, запрет оплаты, конкуренцию, объединения, отсутствие и нехватку остатков, миграцию и устаревшее количество. По умолчанию используется отдельная PGlite в памяти; `CORE_CART_TEST_DATABASE_URL` выбирает отдельную PostgreSQL-базу. В CI она создаётся независимо от основной и wallet-баз.

`tests/cart-store.test.ts` проверяет очередь, откат и rebase при отложенном bootstrap. Браузерные сценарии — `tests/e2e/deferred-cart.spec.ts` и `hydration-controls.spec.ts`; полнота прохождения фиксируется в обзоре проверок.

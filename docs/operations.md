# Operations

The commands below describe the intended setup; they do not establish that production is deployed or that external providers are connected. See [review.md](review.md) for the current status.

Use Node 26 and PostgreSQL 18. `scripts/bootstrap.sh` creates independent `.env.dev` and `.env.prod` with random owner passwords, database passwords, session and mail encryption keys. These files contain secrets and must stay private. Update owner email and SMTP settings; never use the example mailbox in production. See the owner password locally in the relevant environment file. Production configuration must provide a real SMTP URL, sender, ApiPay organization key and webhook secret. Do not change `MAIL_ENCRYPTION_KEY` while encrypted mail jobs remain queued.

Install Docker on Arch by following `scripts/install-docker-arch.sh`. It deliberately requires a local administrator and performs no system upgrade. Without Docker, run `npm run bootstrap`, `npm run db:migrate`, and `npm run dev` for a local PGlite preview at http://localhost:3000. The generated owner credentials are stored in the ignored, private `.secrets/local-credentials.txt`; change the password on first sign-in. `.env.local` and `.data/local` persist the local settings and database. PGlite is local preview storage, not production storage; stop the app before running migrations or another process against it. Its database directory cannot be shared concurrently by the web app and worker, so the local preview does not process queued mail or invoices. Use the PostgreSQL Compose environment to run both services.

Set `URBANMAG_SECRET_DIR` to an absolute directory outside the repository, defaulting to `~/.config/urbanmag`. Bootstrap creates the development Basic Auth password there when Docker is available. If Docker was absent, create it manually with `htpasswd -c "$URBANMAG_SECRET_DIR/dev.htpasswd" urbanmag`. Create a Cloudflare tunnel and save its token to `$URBANMAG_SECRET_DIR/tunnel-token`, mode 600. Do not commit it. Configure the tunnel public hostnames `u.perricheno.com`, `staff-u.perricheno.com`, `dev-u.perricheno.com`, and `staff-dev-u.perricheno.com` to service `http://localhost:8080`. The proxy is bound to localhost; cloudflared uses host networking. Configure Cloudflare to require HTTPS. Only the exact ApiPay webhook path bypasses development Basic Auth; the application verifies its signature. Staff routes must also be guarded by the application zone and authentication checks.

Create the shared frontend networks once: `docker network create urbanmag-prod-frontend` and `docker network create urbanmag-dev-frontend` (bootstrap does this when Docker is available). Start production with `docker compose -p urbanmag-prod --env-file .env.prod -f infra/compose.prod.yml up -d`, and edge with `docker compose -p urbanmag-edge -f infra/compose.edge.yml up -d`. Start development on demand using `docker compose -p urbanmag-dev --env-file .env.dev -f infra/compose.dev.yml up -d`. Development Mailpit is available on host localhost port 8025. Stopping development leaves production running; edge resolves upstream names dynamically. Frontend networks are shared only with web containers; databases remain on separate project networks. Volumes are separate by Compose project and survive `down` without `-v`.

Build one versioned production image sequentially: `docker build -t urbanmag:VERSION .`. Set IMAGE_TAG in `.env.prod` and deploy via `scripts/deploy.sh urbanmag:VERSION`; the script waits for health and attempts to restore the previous image on failure. Do not remove old images until rollback is no longer needed. Persist the working IMAGE_TAG in `.env.prod` after success. Database schema changes must be backward-compatible with the rollback image; image rollback does not reverse migrations.

Set `APIPAY_MODE=sandbox` with an actual sandbox organization key for testing. The worker checks `/account/health` before every request that can create an invoice; it refuses a mismatched organization mode and production demo orders. Set `production` only with a live organization key and webhook secret. Phone invoices are asynchronous; creation is not proof of payment. Register the exact URL `/api/webhooks/apipay` in ApiPay and verify the webhook test. Configure SMTP URL and sender separately per environment. Mock payments are for local development only and are forbidden in production.

Back up with `scripts/backup.sh prod /secure/backup/directory` (or `dev`). The database dump and uploads archive must both be retained; avoid writes while taking a coordinated backup if exact point-in-time consistency is required. Encrypt and store backups elsewhere, and periodically test restoring them. Restore with `scripts/restore.sh dev /secure/backup/directory --replace`; this stops web and worker and replaces the selected database and uploads. Restore to production only after verifying the backup and accepting the replacement. Failures leave services stopped for inspection. Neither deployment nor normal shutdown removes volumes.

## Browser tests and demonstration catalog

Browser tests use an isolated database and mock payments. The test server requires `openssl` to generate a short-lived, self-signed localhost certificate in its test data directory; Playwright accepts that certificate only for the test environment. Run `npm run build`, install Chromium, then run `npm run test:e2e`. Do not reuse the test certificate for deployment.

The local demonstration catalog contains 500 marked demo products across 17 categories. Demo products remain visible for preview, including in production, but the server blocks their sale through real payment flows. Production checkout also stays unavailable until payment and mail settings are configured. Use actual product data for live sales; do not treat demonstration content as inventory.

The shop's service worker caches only its static offline page and local fonts. Store pages and API responses are fetched from the network; cart, account, checkout, staff and other private routes are never stored in the service worker cache.

# Перенос разработки на сервер

Состояние на 14 ноября 2026. Разработка остановлена пользователем; этот коммит сохраняет промежуточную интеграцию для продолжения на сервере. Релиз v0.3.0 не выпущен, production не развернут.

## Ветки

- `dev`, тег `dev/v0.2.0`, коммит `86c0e2a` — проверенная версия, работающая на ноутбуке.
- `feature/integrated-review` — сводка, аналитика и маркетинг сотрудников; профиль, история, подборки, уведомления и помощь; денежный баланс; артикулы и EAN-13. Все объединенные изменения сохранены в истории этой ветки.

После клонирования репозитория на сервере выберите ветку продолжения:

```sh
git fetch origin
git switch --track origin/feature/integrated-review
```

Если локальная ветка уже создана, выполните `git switch feature/integrated-review`, затем `git pull --ff-only origin feature/integrated-review`.

## Проверки перед остановкой

- TypeScript, 64 серверные проверки и production-сборка прошли.
- Последний полный HTTPS E2E: 51 из 52. Последний сценарий получил 429 при входе из-за общего лимита тестовых запросов.
- Изменение тестового IP сохранено; полный набор после него не проверен.
- После исправления неоднозначного селектора сообщения об ошибке отдельно прошли оба сценария баланса, включая возврат сотрудником.
- Lighthouse 94/100 относится к v0.2.0. Интеграция v0.3.0 отдельно не измерялась.
- Временные ссылки на зависимости рабочего дерева вызвали предупреждение standalone-трассировки. Самостоятельный standalone-артефакт кандидата не проверен; на сервере нужна чистая установка зависимостей.

Для продолжения прочитайте `AGENTS.md`, `apps/web/AGENTS.md` и `docs/review.md`. Используйте Node.js 26, `npm ci`, затем typecheck, серверные тесты, сборку и полный HTTPS E2E. Прежде чем менять защиту от частых входов, проверьте обработку заголовков тестового IP: ограничения приложения ослаблять не нужно. Production продвигается после проверок и пользовательского ревью.

## Данные и подключения

Git не содержит секретов, базы, фотографий, зависимостей или собранного приложения. Перенесите `.env.dev`, `.env.prod`, локальный каталог `~/.config/urbanmag`, резервную копию PostgreSQL и `uploads` отдельно защищенным способом. Правила окружений, восстановления и Tunnel — в `docs/operations.md`; не запускайте одновременно старую и новую среду с независимыми копиями рабочих данных.

`WALLET_PRODUCTION_ENABLED=false` сохраняется. Реальные счета, SMTP и процесс урегулирования блокировок требуют отдельного подключения и проверки; ограничения описаны в `docs/wallet.md`. Секреты нельзя помещать в Git, сообщения или логи.

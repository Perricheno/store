# Состояние проекта

Этот обзор описывает реализованные возможности и необходимые дальнейшие подключения. Production пока не развернут; A/B-тестирование не проводилось. Наличие кода, конфигурации или тестового сценария не означает успешного прохождения проверки или работы с реальным поставщиком.

Кандидат v0.4.0 проверен на сервере: TypeScript, все 83 теста, production-сборка и все 66 HTTPS E2E прошли без retry. Из 83 тестов 52 относятся к core, 9 к worker, 22 к корзине, покупательской логике, фильтрам и безопасности. Шесть новых серверных сценариев корзины отдельно прошли на PostgreSQL 18, включая конкурентное добавление, смену размера и повторное применение миграции 6. Браузерные проверки подтверждают сохранение DOM навигации и фактически отрисованного Inter на русском и казахском, открытие прогретой корзины при блокированном следующем RSC-запросе, отсутствие приватных данных в service-worker кэше, серверный HTML без JavaScript, фильтры на 360 и 1440 px и выбор размера на трёх языках. Эти проверки не заменяют нагрузочное тестирование или тестирование реального ApiPay.

В v0.4.0 иконки установки созданы из favicon, текстовый логотип внутри сайта сохранён. Плюс добавляет товар сразу; размер выбирается в корзине с жёлтым предупреждением и серверным запретом оформления без размера. Общая оболочка сохраняется между страницами; шрифты кэшируются на устройстве, предзагрузка ограничена основными вкладками текущего языка. Фильтры получили черновик, применение, сброс, чипы выбранных условий, валидацию цен, историю URL и закреплённые действия. Worker без подключённой интеграции не забирает её задания и не расходует попытки. Полный состав — в манифестах v0.4.0.

Публичная проверка standalone dev выявила ошибку именно Nginx: заголовки RSC передавались служебному auth_request, Next возвращал 307, а Nginx отвечал 500. Внутренняя проверка теперь получает только необходимые заголовки. После `nginx -t` и reload отдельная браузерная проверка через настоящий Tunnel подтвердила четыре перехода без перезагрузки документа, сохранение DOM и шрифта. Публичный dev дополнительно проверен на 360/1440 px, трёх языках, с добавлением и размером в корзине, фильтрами, установочными иконками, noindex и изоляцией staff; проверочная корзина очищена. Отдельные 503 от Cloudflare с `Sec-Purpose: prefetch` относятся к неуспешной спекулятивной предзагрузке HTML из CDN-кэша, описанной в [документации Cloudflare](https://developers.cloudflare.com/speed/optimization/content/speed-brain/); реальные RSC/документы, API и ресурсы прошли без 5xx.

Для выпущенного dev/v0.1.0 проверено 14 ноября 2026: `npm run typecheck`, `npm test`, `npm run build`, 27 проверок core, 3 проверки адаптера ApiPay, проверка ограничения индексации и все 34 HTTPS E2E. E2E охватывают мобильную навигацию, три языка, серверные данные корзины, избранное при первом посещении, тестовую оплату, письмо, смену пароля, историю заказа и действия сотрудника. На публичном dev проверены загрузка каталога и корзины, отсутствие ошибок браузера и успешные ответы API. Это не заменяет пользовательское ревью или проверку реальных платежей.

В v0.2.0 добавлены локализованные характеристики и акции, быстрое добавление, очередь корзины и бегущая строка объявления; компоненты витрины разделены по маршрутам. Проверены typecheck, production-сборка, 38 серверных тестов (29 core, 3 worker, 5 корзины и 1 ограничения индексации) и полный набор 41 HTTPS E2E. После добавления доступного счетчика мобильной корзины повторно прошли production-сборка и все 8 целевых E2E. Проверки включают задержку JavaScript, задержку и отказ запроса корзины, характеристики, акции, бегущую строку и мобильные переходы. На публичном dev подтверждены 6 характеристик товара, диалог выбора размера и запись корзины; исключений JavaScript нет, проверочная корзина очищена.

В кандидате v0.3.0 объединены сводка и SQL-аналитика сотрудников за 7/30/90/365 дней, остатки и качество данных, отдельные маркетинг и помощь; покупательские история, подборки, состав покупок, уведомления и проверка собственных заказов; артикулы и EAN-13; денежный баланс с неизменяемым журналом, пополнением, оплатой и возвратом. Аналитика подтверждает ApiPay событием оплаты, а баланс — соответствующим списанием без возврата; обе ветви требуют production и реальные строки. Production-функции баланса выключены по умолчанию. 14 ноября 2026 (Asia/Almaty) кандидат `5c446ef` проверен на новом сервере в `/root/market/store`, ветка `feature/integrated-review`. После чистого `npm ci` на Node.js 26.13.1 и npm 11.20.0 успешно прошли `npm run typecheck`, `npm test` — все 64 проверки (45 core на PGlite, 7 worker, 6 покупательской логики, 5 корзины и 1 ограничения индексации, без пропусков), `npm run build` — production-сборка Next.js 16.4.6 с webpack без предупреждений, и `npm run test:e2e` — все 52 HTTPS-сценария Chromium за 1 минуту на отдельной тестовой базе с mock-платежами. Прежний результат 51 из 52 до переноса был вызван общим тестовым IP и ответом 429 при входе; сохраненное изменение IP теперь подтверждено полным набором без ослабления защиты приложения. Сценарии баланса и возврата сотрудником также прошли в полном наборе.

Прежний dev на ноутбуке использовал PostgreSQL, worker, тестовую почту Mailpit, Nginx и Cloudflare Tunnel; production-база была подготовлена отдельно, приложение не выпускалось. Ноутбук сейчас недоступен, его текущее состояние не проверено. Пользователь выбрал чистую dev-среду на новом сервере: старые данные не восстанавливались, база создается с нуля, bootstrap генерирует новые секреты, значения которых не публикуются. Первый проверенный запуск dev выполнен из образа `urbanmag:dev-2541e2858413` с OCI revision `2541e285841318931792ca59285130949e709d86`: standalone web и worker работают от UID 1000, web healthy, используются PostgreSQL 18 и Mailpit, uploads доступен для записи. Nginx слушает `127.0.0.1:18080`; существующий systemd Cloudflare Tunnel активен и не изменялся.

Локально через Nginx проверены gate 302, API 401, форма и шрифты 200, безопасная host-only cookie, health dev 200, SSR каталога 200 с noindex, JS 200, API с 500 товарами, изоляция shop/staff с 404, отклонение shop gate cookie на staff и unknown host 444.

Публичный `https://dev-u.perricheno.com/api/health` с новой локально выданной cookie вернул 200 и development, подтвердив новый сервер. Публичный staff-dev: gate 302, вход 303, корень 307/308 сохраняет HTTPS staff origin и ведет на /staff, /staff 200 с noindex, /api/staff/products 401 без staff session, /ru 404 на staff host. Пароли не менялись.

Публичная проверка Chromium на 360 и 1440 px подтвердила каталог, корзину и профиль: 200, без горизонтального переполнения, ошибок JavaScript и 5xx; наблюдаемые JS и шрифты — 200. На 360 px нижние действия доступны над навигацией, значки нижних карточек появляются при прокрутке. Начальный пароль владельца принят и требует смены; проверочная сессия завершена.

Начальный бэкап нового dev восстановлен в изолированной PostgreSQL 18: 500 товаров, миграции 1–5 и один owner, архив uploads читается; подробности в `docs/transfer-state.md`. Индексация временных доменов выключена.

До переноса резервирование прежнего dev проверено фактическим восстановлением дампа в отдельную временную PostgreSQL-базу: восстановлены 500 товаров, временная база удалена после проверки. На момент той проверки архив фотографий читался; каталог резервной копии имел права 0700, файлы — 0600.

Измерение production-сборки v0.2.0 в Lighthouse Mobile: Performance 94, Accessibility 100, Best Practices 100, LCP 1,56 с, TBT 276 мс, CLS 0. Неизмененный dev/v0.1.0 в сопоставимом предыдущем прогоне: Performance 78, LCP 1,667 с, TBT 923 мс, CLS 0. Параметры и ограничения сохранены в [результате измерения](performance/dev-v0.2.0.json). Это одиночные лабораторные прогоны на изолированной HTTPS-сборке с 500 тестовыми товарами без фотографий, а не оценка пропускной способности production. Кандидат v0.3.0 в Lighthouse отдельно не измерялся. Реальные изображения и подключения требуют отдельной проверки.

Короткая локальная проверка прогретого API на PGlite: 501 запрос за 5 секунд при трех параллельных соединениях, ошибок 0, p50 27 мс, p95 42 мс. Этот результат не определяет пропускную способность production.

Доступ к dev защищен формой с подписанной host-only Secure HttpOnly cookie сроком на 30 дней. Навигация и элементы управления используют иконки Bold; иконки категорий Regular имеют размер 80 px на мобильных и 104 px на широких экранах, черный цвет с прозрачностью 0,16. Нижняя мобильная навигация расположена на 12 px выше края с учетом безопасной зоны. Видимые надписи DEMO удалены, серверный признак `isDemo` и запрет реальных счетов для таких товаров сохранены.

Прежняя сборка изолированного worktree с временными ссылками на зависимости выдавала предупреждение о 27 файлах standalone вне корня трассировки. После чистого `npm ci` на новом сервере production-сборка завершилась без этих предупреждений. Браузерные E2E используют тестовый Next-сервер; standalone-артефакт отдельно проверен на работающем dev. Дополнительно core suite прошел 45 из 45 на изолированном PostgreSQL 18: core и wallet использовали отдельные базы PostgreSQL, staff insights — PGlite. Чистая установка зависимостей в CI и реальные платежи требуют отдельных фактических проверок. Операционные ограничения баланса и ручного урегулирования сохранены в [docs/wallet.md](wallet.md).

Команды проверок и порядок запуска приведены в [README](../README.md). `npm run typecheck` проверяет TypeScript веб-приложения и core; `npm test` запускает тесты core, worker, безопасности, корзины и покупательской логики; `npm run build` собирает веб-приложение; `npm run test:e2e` запускает браузерные сценарии с отдельной тестовой базой и mock-платежами. Проверка core на PostgreSQL требует отдельной пустой тестовой базы; такой запуск также описан в конфигурации CI. Итог текущих запусков сборки, браузерных тестов и CI следует подтверждать их фактическими результатами.

Проверка GitHub CI коммита `9c56929` выявила отдельную гонку начальной загрузки аналитики: второй запрос после общей загрузки кабинета убирал ошибку и кнопку «Повторить». Причина воспроизведена управляемой задержкой ответа; начальная загрузка отделена от явного обновления, регрессионный E2E проверяет оба действия. После исправления прошли TypeScript, production-сборка, 8 из 8 последовательных целевых запусков с `CI=true` без retry или sleep и весь набор 52 HTTPS E2E с `CI=true` за 1,2 минуты. Текущий образ развертывания задается приватным `IMAGE_TAG` в `.env.dev`; исходный коммит хранится в OCI label `org.opencontainers.image.revision`.

# Состояние проекта

Этот обзор описывает реализованные возможности и необходимые дальнейшие подключения. Production пока не развернут; A/B-тестирование не проводилось. Наличие кода, конфигурации или тестового сценария не означает успешного прохождения проверки или работы с реальным поставщиком.

Для выпущенного dev/v0.1.0 проверено 14 ноября 2026: `npm run typecheck`, `npm test`, `npm run build`, 27 проверок core, 3 проверки адаптера ApiPay, проверка ограничения индексации и все 34 HTTPS E2E. E2E охватывают мобильную навигацию, три языка, серверные данные корзины, избранное при первом посещении, тестовую оплату, письмо, смену пароля, историю заказа и действия сотрудника. На публичном dev проверены загрузка каталога и корзины, отсутствие ошибок браузера и успешные ответы API. Это не заменяет пользовательское ревью или проверку реальных платежей.

В v0.2.0 добавлены локализованные характеристики и акции, быстрое добавление, очередь корзины и бегущая строка объявления; компоненты витрины разделены по маршрутам. Проверены typecheck, production-сборка, 38 серверных тестов (29 core, 3 worker, 5 корзины и 1 ограничения индексации) и полный набор 41 HTTPS E2E. После добавления доступного счетчика мобильной корзины повторно прошли production-сборка и все 8 целевых E2E. Проверки включают задержку JavaScript, задержку и отказ запроса корзины, характеристики, акции, бегущую строку и мобильные переходы. На публичном dev подтверждены 6 характеристик товара, диалог выбора размера и запись корзины; исключений JavaScript нет, проверочная корзина очищена.

В кандидате v0.3.0 объединены сводка и SQL-аналитика сотрудников за 7/30/90/365 дней, остатки и качество данных, отдельные маркетинг и помощь; покупательские история, подборки, состав покупок, уведомления и проверка собственных заказов; артикулы и EAN-13; денежный баланс с неизменяемым журналом, пополнением, оплатой и возвратом. Аналитика подтверждает ApiPay событием оплаты, а баланс — соответствующим списанием без возврата; обе ветви требуют production и реальные строки. Production-функции баланса выключены по умолчанию. Локальные проверки кандидата: `npm run typecheck`, `npm test` — 64 успешных проверки (45 core на PGlite, 7 worker, 6 покупательской логики, 5 корзины и 1 ограничения индексации), production-сборка. Последний полный HTTPS E2E завершился результатом 51 из 52: оставшийся сценарий получил 429 при входе из-за общего лимита тестового IP. После изменения тестового IP полный набор повторно не проверен: работа остановлена пользователем для переноса на сервер. После исправления неоднозначного селектора alert отдельно прошли 2 сценария баланса, включая возврат сотрудником.

Dev работает с PostgreSQL, worker, тестовой почтой Mailpit, Nginx и Cloudflare Tunnel. Production-база подготовлена отдельно; production-приложение еще не выпущено. Индексация временных доменов выключена.

Резервирование dev проверено фактическим восстановлением дампа в отдельную временную PostgreSQL-базу: восстановлены 500 товаров, временная база удалена после проверки. Архив фотографий читается; каталог резервной копии имеет права 0700, файлы — 0600.

Измерение production-сборки v0.2.0 в Lighthouse Mobile: Performance 94, Accessibility 100, Best Practices 100, LCP 1,56 с, TBT 276 мс, CLS 0. Неизмененный dev/v0.1.0 в сопоставимом предыдущем прогоне: Performance 78, LCP 1,667 с, TBT 923 мс, CLS 0. Параметры и ограничения сохранены в [результате измерения](performance/dev-v0.2.0.json). Это одиночные лабораторные прогоны на изолированной HTTPS-сборке с 500 тестовыми товарами без фотографий, а не оценка пропускной способности production. Реальные изображения и подключения требуют отдельной проверки.

Короткая локальная проверка прогретого API на PGlite: 501 запрос за 5 секунд при трех параллельных соединениях, ошибок 0, p50 27 мс, p95 42 мс. Этот результат не определяет пропускную способность production.

Доступ к dev защищен формой с подписанной host-only Secure HttpOnly cookie сроком на 30 дней. Навигация и элементы управления используют иконки Bold; иконки категорий Regular имеют размер 80 px на мобильных и 104 px на широких экранах, черный цвет с прозрачностью 0,16. Нижняя мобильная навигация расположена на 12 px выше края с учетом безопасной зоны. Видимые надписи DEMO удалены, серверный признак `isDemo` и запрет реальных счетов для таких товаров сохранены.

Сборка изолированного worktree с временными ссылками на зависимости выдала предупреждение о 27 файлах standalone вне корня трассировки; браузерная проверка использует тестовый Next-сервер. Самостоятельный standalone-артефакт из этого worktree не проверялся. PostgreSQL, чистая установка зависимостей в CI, публичное окружение кандидата и реальные платежи требуют отдельных фактических проверок. Операционные ограничения баланса и ручного урегулирования сохранены в [docs/wallet.md](wallet.md).

Команды проверок и порядок запуска приведены в [README](../README.md). `npm run typecheck` проверяет TypeScript веб-приложения и core; `npm test` запускает тесты core, worker, безопасности, корзины и покупательской логики; `npm run build` собирает веб-приложение; `npm run test:e2e` запускает браузерные сценарии с отдельной тестовой базой и mock-платежами. Проверка core на PostgreSQL требует отдельной пустой тестовой базы; такой запуск также описан в конфигурации CI. Итог текущих запусков сборки, браузерных тестов и CI следует подтверждать их фактическими результатами.

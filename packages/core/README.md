# Urbanmag core

The shared TypeScript service is the authority for catalog visibility, prices, cart totals, roles, order access, inventory reservations and payment state. HTTP handlers must obtain visitor and user IDs from their own signed/opaque cookies and authenticated sessions; never accept those identity fields from request bodies. `processPaymentEvent` accepts trusted events only, after the HTTP layer has verified the provider HMAC and payment environment.

`initCore()` runs idempotent PostgreSQL SQL migrations and creates 12 visibly marked demonstration products. `DATABASE_URL` selects PostgreSQL (the deployment targets PostgreSQL 18). With no URL, development/test uses PGlite at `PGLITE_DATA_DIR` (default `.data/core`). PGlite serializes all operations because it has a single connection; production PostgreSQL uses row locks and a connection pool. Drizzle schema definitions are in `src/schema.ts`, and `getDrizzle()` exposes the initialized driver.

`APP_ENV=production` requires `DATABASE_URL`, a 32-character-or-longer `APP_SECRET`, `MAIL_ENCRYPTION_KEY` encoding exactly 32 random bytes (hex/base64), and `APIPAY_MODE=sandbox|production`. `BOOTSTRAP_OWNER_EMAIL` and `BOOTSTRAP_OWNER_PASSWORD` create the first owner only if none exists; there are no default credentials. Owner and staff bootstrap passwords must be changed before privileged operations. Authentication uses Argon2id passwords and SHA-256 hashes of opaque session/reset/access tokens. Buyer and staff sessions have separate realms.

Checkout locks the visitor's cart and catalog prices, then allocates inventory by variant and branch in stable lock order. Replays with the same visitor/key/body return the original order; changed payloads or carts conflict. Entering an existing email never grants account/order access. New accounts receive a 24-hour temporary password and single-use claim link inside an AES-256-GCM encrypted email job. A successful password claim/reset revokes existing sessions.

Inventory is stored per branch. `setInventory(actorId, variantId, quantity, branchId='main')` creates or updates a branch stock row. Public availability is the sum of unreserved branch stocks. Reservations remain until a verified provider cancelled/expired event; `expireReservations()` intentionally does not infer provider status from wall-clock time. Paid events consume a reservation once. Late paid orders enter `manual_review`; refunds do not automatically restock goods. Cancelling a paid order creates `refund_required`, and cancellation of an active unpaid invoice requires provider confirmation. Live payments for demo variants and mock payments in production are rejected.

The worker uses `claimJob`, `finishJob`, `failJob`, `decryptMailPayload`, `getInvoiceOrder`, `recordInvoice` and `listPendingInvoices`. Jobs use a five-minute lease, bounded exponential retries and a maximum of eight attempts. Pass the same worker ID to claim/finish/fail to prevent a stale worker from finishing a reclaimed job. Invoice creation must send the order ID as the provider idempotency key. All stored invoices, including expired/cancelled invoices, remain eligible for provider reconciliation to detect late payments. Finished email job payloads are erased.

Run `npm run test --workspace @urbanmag/core` for isolated in-memory database tests. `CORE_TEST_DATABASE_URL` opts into running against a **fresh, disposable** PostgreSQL database instead. Tests cover last-unit checkout races, branch allocation, checkout replays, token isolation/rotation, encrypted mail, provider associations, early webhooks, late payments, refunds and worker claiming. The full suite also passes against a fresh PostgreSQL 18 Docker database, exercising real pooled connections and row-lock concurrency.

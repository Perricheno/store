# Urbanmag

Интернет-магазин одежды на Next.js с русской, казахской и английской локализациями. В проекте есть каталог, поиск и фильтры, карточки товаров, избранное, корзина, оформление и просмотр заказов, учетные записи покупателей и отдельный интерфейс сотрудников. Для локальной демонстрации предусмотрен каталог из 500 демонстрационных товаров в 17 категориях; служебный признак хранится на сервере без бейджей в витрине, а позиции защищены от продажи через реальные платежи, в том числе в production. Каталог показывает по 24 товара с возможностью загрузить следующие.

Выпуск v0.4.0 развернут в [production](https://u.perricheno.com) и [dev](https://dev-u.perricheno.com); кабинеты сотрудников — [production](https://staff-u.perricheno.com) и [dev](https://staff-dev-u.perricheno.com). Отдельные [prod-релиз](https://github.com/Perricheno/store/releases/tag/prod/v0.4.0) и [dev-релиз](https://github.com/Perricheno/store/releases/tag/dev/v0.4.0) указывают на проверенный коммит `316aed50f5bf`. PostgreSQL, файлы, ключи и сессии окружений изолированы. Оформление production выключено до подключения ApiPay и SMTP; индексация и production-баланс выключены. Фактические проверки и ограничения — в [обзоре](docs/review.md).

Общая оболочка сохраняет шапку и навигацию между страницами, основные вкладки предзагружаются. Иконки установки приложения получены из favicon; локальные шрифты кэшируются на устройстве без сохранения приватных страниц или API.

На мобильных экранах доступны нижняя навигация и компактный переключатель языка. При загрузке или отсутствии фотографии показывается тонкая светлая иконка категории с мягким бликом в статичной маске; анимация приостанавливается вне экрана, после загрузки фотографии и при настройке уменьшения движения. Корзина и оформление получают начальные данные корзины с сервера. Изменения корзины отображаются сразу, последовательно сохраняются и сверяются с сервером перед оформлением. Плюс на карточке сразу добавляет товар без диалога: размер выбирается в корзине, невыбранный размер отмечен жёлтым «!». Сервер запрещает оформление до выбора. Менять размер можно в самой корзине, одинаковые варианты объединяются. Подробности — [корзина и размеры](docs/cart-sizes.md).

Владелец может заполнить информационные страницы и контакты на трех языках, а также включить объявление и баннер. Объявление выводится бегущей строкой с управлением паузой. Сотрудники могут редактировать локализованные характеристики и подписи акций товаров. По умолчанию тексты пусты, объявление и баннер выключены; выводятся только сохраненные контактные данные.

В профиле доступны состав покупок, текущие уведомления и проверка собственных заказов, история просмотров на устройстве с очисткой и выключением, подборки и помощь по контактам магазина. Карточка товара поддерживает отправку ссылки, необязательный артикул и EAN-13 выбранного варианта. Кабинет сотрудников открывается сводкой; аналитика считает подтверждённые production-продажи реальных товаров по всей истории базы и показывает исключения качества данных.

Денежный баланс покупателя хранит средства и неизменяемые проводки отдельно для mock, sandbox и production. Доступны пополнение через ApiPay, оплата заказа и полный возврат сотрудником. Production-функции выключены по умолчанию; блокировки, ручная проверка и условия включения описаны в [docs/wallet.md](docs/wallet.md).

Общий серверный модуль отвечает за товары, роли, остатки и резервирование, заказы и состояние платежей. Worker обрабатывает очередь писем и запросы счетов ApiPay. Реальная интеграция требует отдельных внешних настроек и проверки; создание счета само по себе не подтверждает оплату.

## Локальный запуск

Нужен Node.js 26. В корне проекта:

```sh
npm ci
npm run bootstrap
npm run db:migrate
npm run dev
```

Откройте http://localhost:3000. Bootstrap создает приватные `.env.local` и `.secrets/local-credentials.txt` и не перезаписывает их; пароль владельца хранится во втором файле. Локальная база PGlite предназначена для просмотра одним процессом: отдельный worker одновременно с веб-приложением использовать нельзя, поэтому письма и счета в этом режиме не обрабатываются.

Для полной среды требуются PostgreSQL, отдельный worker, SMTP и настроенный ApiPay. Подготовка Docker на Arch, изолированные окружения, Cloudflare Tunnel, резервное копирование и восстановление описаны в [docs/operations.md](docs/operations.md). Предусмотренные адреса: `u.perricheno.com`, `staff-u.perricheno.com`, `dev-u.perricheno.com`, `staff-dev-u.perricheno.com`. Их наличие в конфигурации не означает, что развертывание или внешние интеграции уже проверены. Индексация поисковыми системами отключена до отдельного включения.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Модуль `apps/web/src/lib/cart-store.ts` управляет состоянием и очередью корзины; его тесты входят в `npm test` и отдельно запускаются командой `npx tsx --test tests/cart-store.test.ts`. Компоненты витрины разделены по маршрутам в `apps/web/src/components/shop-*.tsx`.

E2E использует production-сборку, отдельную тестовую базу и mock-платежи. Для HTTPS тестовый сервер создает временный самоподписанный сертификат через OpenSSL; Chromium доверяет ему только в тестовой конфигурации. Для PostgreSQL-интеграционных тестов нужен отдельный пустой экземпляр; подробности в [packages/core/README.md](packages/core/README.md). Не используйте реальные платежные данные при тестировании.

Текущее состояние модулей и оставшиеся подключения описаны в [docs/review.md](docs/review.md). Команды выше задают порядок проверок и сами по себе не подтверждают их успешное прохождение.

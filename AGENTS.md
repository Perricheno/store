# Правила работы с Urbanmag

- `apps/web` — Next.js, витрина, кабинет и HTTP API; сначала прочитайте `apps/web/AGENTS.md` и соответствующую документацию установленной версии Next.js. `apps/worker` — обработчик писем и счетов; `packages/core` — данные, бизнес-правила и миграции. `infra`, `scripts` и `docs` содержат окружения и операции.
- Node.js 26; устанавливайте зависимости через `npm ci`. Проверки: `npm run typecheck`, `npm test`, `npm run build`, затем `npm run test:e2e` с установленным Chromium. E2E запускает отдельный тестовый сервер и использует тестовые данные и mock-платежи. Не заявляйте об успешной проверке, которую не выполняли.
- Для локального просмотра используйте `npm run bootstrap`, `npm run db:migrate`, `npm run dev`. PGlite допускает один процесс: не запускайте с ним отдельный worker. Для полной среды нужны PostgreSQL, worker, SMTP и настройки ApiPay; инструкции в `docs/operations.md`.
- Никогда не добавляйте ключи, пароли, токены, реальные конфигурации окружений или клиентские данные в Git, сообщения и логи. Используйте `.env.example` как перечень переменных.
- Все новые пользовательские строки поддерживайте на русском, казахском и английском. Сохраняйте визуальную систему: белый, черный и красный; стили компонентов — CSS Modules. Не переводите проект на Vite и не используйте Sites для реализации этого репозитория.
- После каждого значимого завершенного изменения создавайте локальный Git-коммит: короткий заголовок и содержательное тело со списками Added, Improved, Fixed, Changed, Removed. Указывайте только реально выполненные изменения; пустые категории обозначайте «Нет». Не включайте чужие изменения без разрешения. До первого коммита настройте локальные имя и email автора.
- Релизы dev и production ведите отдельно: аннотированные теги `dev/vX.Y.Z` и `prod/vX.Y.Z`. Production продвигает тот же проверенный SHA из dev; не публикуйте незавершенный код и не выдумывайте результаты проверок. Релизные заметки на русском содержат полный список фактических изменений по всем пяти категориям, окружение, короткий SHA и URL. Публикация на GitHub выполняется только явно через `--publish`; не продвигайте релиз автоматически. См. `docs/releases/README.md`.
- Для сложных задач используйте GPT-6.1 Sol, для задач средней и меньшей сложности — GPT-6.1 Terra.
